01 / השורה התחתונה

מה זה פותר?

קבצי Power BI הם לא רק צילום מסך: פרויקט PBIP מפריד את המודל ואת הגדרות הדוח לקבצים שאפשר לקרוא, לשנות ולבקר. לעוזר קוד כללי אין בהכרח הבנה של TMDL, PBIR, DAX, כללי אימות וגבולות השירות. המאגר PBI_Agentic_Dev של Tim / InsightfulAnalytics מספק marketplace של תוספים ממוקדים. הוא fork מותאם של הפרויקט המקורי של Kurt Buhler / Data Goblins, לא מוצר רשמי של Microsoft ולא סוכן עצמאי שעושה הכול לבד.

הבחנה חשובה: התקנת plugin נותנת לעוזר הוראות, תהליכים ובחלק מהמקרים כלי אימות. היא אינה הוכחה שהדוח נפתח, שהמספרים נכונים או שההרשאות עובדות.

02 / מתחת למכסה המנוע

מה נמצא במאגר?

PBIP ומודלים

pbip מכסה את מבנה הפרויקט, TMDL להגדרת מודל ו-PBIR להגדרת דוח. semantic-models עוסק ב-DAX, Power Query, ביצועים ורענון. חלק מהתוספים כוללים hooks שבודקים מבנה או הפניות אחרי שינוי.

דוחות ועיצוב

reports מספק מיומנויות לבנייה ובדיקת דוחות; custom-visuals מכסה בין היתר Deneb, Python ו-SVG. יש תהליכי צילום מסך והשוואה, אבל זמינותם תלויה בכלים ובסביבה.

Desktop, Fabric, Tabular Editor

קיימים תוספים נפרדים לחיבור למודל Desktop, לכלי Fabric ול-Tabular Editor. אלו מסלולים עם תנאי סביבה, הרשאות ותלות בכלים חיצוניים, לא יכולת שמתקבלת אוטומטית מכל התקנה.

Skills, agents ו-hooks

Skills הם ידע ותהליך שהעוזר טוען למשימה; agents מחלקים סקירה ואימות; hooks מפעילים בדיקות לפי אירוע. בקובץ .claude-plugin/marketplace.json מופיעים עשרה תוספים. גרסת manifest שנקראה: 26.26.

לדוגמה, טענת ביצועים מתוך הניסוי של Timothy Osborn ב-BiNexus אינה משהו שעוזר יכול להסיק מצורת הוויזואל בלבד: שם נמדדו תשע גרסאות של דוח P&L ב-Performance Analyzer. זה שימוש מצוין לסוכן שמכין חלופות, אבל המספרים נמדדים בסביבתכם. במאמר נוסף שלו על גודל ה-canvas נידונות השפעות על מובייל, embed וייצוא: סיבה לבדוק גם את מה שרואים, לא רק JSON תקין.

03 / מסלול עבודה

איך מתחילים בפועל?

  1. פתחו עותק עבודה של הפרויקט

    התחילו מ-PBIP שמנוהל ב-Git או מגיבוי. שמרו עבודה קיימת, הגדירו משימה צרה ותוצאה צפויה. אם יש מידע רגיש, הגדירו גבולות גישה לפני הפעלת עוזר וכלי צד שלישי.

  2. רשמו את ה-marketplace ב-Claude Code

    לפי README של המאגר, מריצים במסוף:

    claude plugin marketplace add InsightfulAnalytics/PBI_Agentic_Dev

    שם ה-repo שונה משם ה-marketplace: אחרי הרישום משתמשים ב-power-bi-agentic-dev.

  3. התקינו רק את מה שצריך

    לעבודה על קבצי פרויקט ומודל אפשר להתחיל ב-pbip וב-semantic-models. לדוח מוסיפים reports. לדוגמה:

    claude plugin install pbip@power-bi-agentic-dev
claude plugin install semantic-models@power-bi-agentic-dev
claude plugin list

    עיינו בתוכן ובהיקף plugin לפני הפעלה. אין צורך להתקין את כל עשרת התוספים.

  4. תנו לעוזר משימה שאפשר לבדוק

    למשל: "סקור את פרויקט ה-PBIP הזה. הצע שינוי אחד במודל שמקטין כפילות DAX; הצג diff, אמת מבנה וקשרים, ואל תפרסם או תשנה סביבת ייצור. כתוב מה לא בדקת ב-Desktop." בקשו שלבים קטנים, diff, תוצאות בדיקות ודרך חזרה.

  5. בדקו ידנית לפני מסירה או פרסום

    בדקו Git diff, הריצו בדיקות רלוונטיות, פתחו את הפרויקט ב-Power BI Desktop אם הוא זמין, ודאו שהוא נטען, שהוויזואלים והמספרים נכונים, ואז בדקו אינטראקציות, הרשאות ופרסום בסביבה מתאימה. בדיקת schema לבדה אינה מחליפה פתיחה ורינדור.

כלים אחרים: README מתעד גם התקנה ב-Copilot CLI דרך marketplace או נתיב של plugin יחיד, וב-Codex דרך python codex/install.py --check לפני התקנה. ב-Codex חלק מהיכולות מותאמות כ-checklists ולא כ-subagents/hooks אוטומטיים; ב-Copilot ההתקנה לפי README היא ברמת המשתמש. עברו להוראות המקור המעודכנות לפני התקנה.
04 / מה לא מובטח

גבולות שחשוב להכיר

אימות אינו רינדור

בדיקות TMDL/PBIR יכולות לתפוס שגיאות מבניות, אך לא להוכיח שתוכן הדוח נכון, קריא ונגיש, או שמודל פועל תחת RLS/OLS. אל תציגו בדיקה סטטית כבדיקת Desktop.

הסביבה קובעת

לפי README, ב-Linux אין Power BI Desktop מקומי או pbir CLI, בעוד חלק מהבדיקות והייצוא אפשריים דרך שירות. חיבור למודל חי, Fabric או Tabular Editor דורש כלים, הרשאות ותצורה מתאימים.

הקוד מתעדכן

זה fork שמסנכרן upstream באופן סלקטיבי. יש בו מיומנויות המסומנות WIP, ותוכן שנוצר בעזרת AI והמחבר עצמו מזהיר שעשוי לכלול טעויות. בדקו גרסה ושינויים לפני שימוש.

עיצוב וביצועים דורשים מדידה

מאמר המעקפים הוויזואליים של BiNexus מזכיר שלטריקים עיצוביים יש מחיר תחזוקה. אין לקחת מדידות ממאמר אחר כהבטחה על המודל שלכם; מדדו ועברו על התוצאה במסכים אמיתיים.

מה נבדק כאן: קראתי את README, ה-LICENSE, ה-marketplace manifest, מבנה התוספים, רשימת שינויי ה-fork ומאמרים בבלוג BiNexus. לא התקנתי את התוספים, לא הרצתי אותם על PBIP, לא פתחתי Power BI Desktop ולא אימתתי תוצאות על דוח חי. המדריך הזה הוא הסבר והתחלה, לא דוח בדיקות של הכלי.
